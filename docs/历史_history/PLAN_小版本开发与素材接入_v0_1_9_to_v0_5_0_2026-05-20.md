# 小版本开发与素材接入规划（v0.1.9 -> v0.5.0）

Marble Dominion: Cardfront 小版本开发与素材接入规划
基于 GitHub 仓库当前 v0.1.8e 状态；覆盖 v0.1.9 → v0.5.0；重点包含高耦合拆分、正式 UI、assets 全量素材接入与测试验收
0. 文档定位
这份文档用于指导 MarbleDominion-Cardfront 后续开发。它不是宏观愿景稿，而是面向实际执行的小版本路线图：每个版本都限定目标、改动范围、禁止事项、测试要求和验收标准。
核心原则：先工程收口，再拆高耦合；先正式 UI，再扩卡牌；先接入 assets 中已有素材，再生成或引入新素材；先建立测试和性能预算，再推进 Deck、AI、Save/Load。
特别说明：仓库 assets/cardfront/ 下现有 11 个 AI 生成素材均纳入后续接入规划，不丢弃、不绕过；其中完整背景素材需要裁切、透明化、缩放和缩略图生成后再进入运行时。

5. v0.2.1 美术资源接入阶段

5.1 assets 总体接入原则
assets/ 只放整理后的可导入素材，不放原始下载包。
每类素材必须有来源与授权说明；Game-Icons 使用时保留 CC BY 3.0 致谢。
Cardfront AI 生成素材仅限本项目使用，不作为第三方素材包分发。
UI 先用现有 Kenney / Wenrexa / Game-Icons；不急着额外生成新 UI。
Cardfront 卡牌插图、装置精灵、VFX 纹理按 v0.2.1b/c/d 分批进入运行时。
完整背景图不得直接用作小 sprite；必须生成 runtime_512 / 256 / 128 / 96 / 64 / 48 / 32 等版本。
