# BallWar / 领土战争 v1.9.32

本版为“事件转盘系统”当前规划规格整合版，用作后续开发实现基线。

目标不是直接替炮台开火，而是把全局随机性收束到控制仓体系内，让事件能干预战局，但不破坏“控制仓决定炮台发射”的核心玩法。

## 核心定位

事件转盘是全局随机事件系统，不直接操作炮台，而是干预某个阵营的控制仓状态。

核心原则：

```text
不直接让炮台开火
不绕过控制仓
随机性必须可见
事件结果要能影响 pending_count、控制球、控制仓状态
```

设计分层：

```text
控制仓 = 微观随机
事件转盘 = 宏观随机
```

控制仓负责“球自己怎么掉”，转盘负责“本轮战局发生什么综艺式变化”。

## 转盘流程

采用两段式综艺转盘：

```text
事件预告：转盘启动
颜色快速轮转
颜色停下：锁定阵营
效果快速轮转
效果停下：锁定效果
弹出事件提示
应用结果
中央横幅显示约 2 秒
```

示例：

```text
【事件转盘】
红方
本次 x3！
```

或：

```text
【控制仓短路】
蓝方控制仓封锁 5 秒！
```

右下角 HUD 建议显示：

```text
事件：红方 x3
下次事件：00:28
```

## “本次”的定义

本次 = 目标控制仓当前的 `pending_count`。

例如红方当前：

```text
pending_count = 16
```

则：

```text
本次 +10 => pending_count = 26
本次 x2  => pending_count = 32
本次 x3  => pending_count = 48
```

所有结果都受当前模式的单次发射上限限制：

| 模式 | 单次发射上限 |
| --- | ---: |
| 基础模式 | 2048 |
| 占领模式 | 2048 |
| 限时模式 | 2048 |
| 狂野模式 | 2187 |

## 锁定中处理规则

第一版稳定规则：

```text
控制仓未锁定：事件立即作用于 pending_count
控制仓锁定中：正向 pending_count 类事件转为“下一轮生效”
控制仓干扰类事件立即生效
```

也就是：

```text
+10 / x2 / x3 / 加1球
```

如果目标控制仓正在发射，则不直接修改当前 burst，而是存入“下一轮修正”。

但“控制仓干扰”例外，因为它本身就是打断类事件，可以立即取消当前发射。

## 效果轮盘

第一版共有 6 个效果，全部等概率：

```text
每个效果概率 = 1/6
```

### 1. 重转

规则：

```text
只重转效果，不重转颜色
```

例如：

```text
颜色已经锁定为蓝方
效果转到“重转”
=> 蓝方重新抽一次效果
```

限制：

```text
最多连续重转 2 次
超过后强制变成本次 +10
```

### 2. 本次 +10

规则：

```text
目标阵营 pending_count += 10
不超过当前模式单次发射上限
```

控制仓已满或锁定时，也可以作为下一轮修正存储。

### 3. 本次 x2

规则：

```text
目标阵营 pending_count *= 2
不超过当前模式单次发射上限
```

可与控制仓内倍率口效果叠加，但统一受上限约束。

### 4. 本次 x3

规则：

```text
目标阵营 pending_count *= 3
不超过当前模式单次发射上限
```

狂野模式与控制仓倍率口常驻 `x3`、上限 `2187` 的设定天然兼容；非狂野模式也可抽到 `x3`。

### 5. 加 1 球进控制仓

规则：

```text
目标阵营控制仓 +1 控制球
如果控制仓未满：直接加入 1 个控制球
如果控制仓已满：转化为 pending_count +10
```

这样事件不会浪费，也不会绕过控制仓直接开火。

### 6. 控制仓干扰

命名推荐：

```text
控制仓干扰
控制仓短路
禁门
封锁
```

规则：

```text
持续 5 秒
x2 / x3 / 发射口全部关闭
控制球不能落入任何口
控制球碰到底部门口会被弹回或重新抛起
期间不能触发倍率，也不能触发发射
```

如果目标阵营当前正在发射：

```text
取消当前剩余发射
控制仓立即解除发射锁定
pending_count 回退为 max(1, floor(剩余发射数 * 0.25))
再进入 5 秒干扰状态
```

## 颜色轮盘公平机制

颜色轮盘不是四方绝对平均，而是根据局势做权重修正。

基础排名权重：

| 当前排名 | 权重 |
| --- | ---: |
| 第一名 | 0.8 |
| 第二名 | 1.0 |
| 第三名 | 1.15 |
| 第四名 | 1.3 |

### 正面事件

包括：

```text
本次 +10
本次 x2
本次 x3
加 1 球
```

倾向落后阵营：

```text
第一名权重低
第四名权重高
```

目的：防止滚雪球，让局势更胶着。

### 负面事件

包括：

```text
控制仓干扰
```

倾向领先阵营：

```text
第一名权重高
第四名权重低
```

目的：避免落后者被进一步打崩。

### 中性事件

包括：

```text
重转
```

规则：

```text
四方均等
每个阵营权重 = 1.0
```

## 各模式触发频率

### 基础模式

```text
开局 60 秒后开始
每 60 秒触发一次
```

### 占领模式

```text
开局 30 秒后开始
每 40 秒触发一次
```

终局提速：

```text
最高占领率 >= 65% 后
事件间隔从 40 秒缩短到 30 秒
```

### 限时模式

建议按“剩余时间”而不是总时长写死：

```text
开局 30 秒后开始
剩余时间 > 120 秒：每 45 秒
60 秒 < 剩余时间 <= 120 秒：每 30 秒
剩余时间 <= 60 秒：每 20 秒
```

这样可以兼容当前 5 到 15 分钟的限时配置。

### 狂野模式

```text
开局 20 秒后开始
每 20 到 30 秒触发一次
后期预留加强事件
```

第一版实现可直接采用：

```gdscript
next_event_interval = randf_range(20.0, 30.0)
```

## 与现有系统关系

当前工程已经具备这些基础：

```text
game_mode
pending_count
control_chamber lock
turret burst
time_limit
wild x3
save slots
```

不建议把事件系统继续塞回 `Main.gd`，应新增模块：

```text
EventRouletteController.gd
```

职责：

```text
管理事件计时
根据模式决定触发间隔
根据事件类型选择阵营
执行颜色轮盘和效果轮盘
向 ControlChamber / Turret / Main 发信号
显示事件 UI
记录当前事件状态
写入存档字段
```

`Main.gd` 只负责创建它、传入引用、接收少量结果信号。

## 与当前脚本的对接建议

当前代码结构已经基本适合接入：

- `scripts/Main.gd`
  - 已负责模式选择、全局计时、场景创建、HUD 创建、存档槽读写。
- `scripts/ControlChamber.gd`
  - 已有 `pending_count`、`is_locked`、`locked_remaining`、`add_control_ball()`。
- `scripts/Turret.gd`
  - 已有 `fire_burst()`、`burst_progress`、`burst_lock_changed`。

第一版建议由 `EventRouletteController.gd` 持有：

```text
Main 引用
chambers 引用
turrets 引用
当前模式
当前倒计时
最近一次事件结果
```

然后通过公开接口和信号衔接，而不是直接在多个脚本之间散写逻辑。

## 建议新增接口

控制仓建议预留：

```gdscript
func apply_pending_bonus(amount: int) -> void
func apply_pending_multiplier(multiplier: int) -> void
func add_control_ball_from_event() -> void
func apply_jammed(duration: float) -> void
func queue_next_round_modifier(modifier: Dictionary) -> void
func cancel_current_burst_with_refund(ratio: float) -> void
```

炮台建议预留：

```gdscript
func cancel_burst() -> int
```

返回被取消的剩余发射数，用于：

```text
pending_count = max(1, floor(remaining * 0.25))
```

## 存档字段预留

建议增加：

```text
event_roulette_enabled
next_event_time_left
current_event_interval
last_event_faction
last_event_effect
reroll_count
queued_round_modifiers
jammed_time_left_per_faction
```

第一版不一定全部读写，但建议先按兼容扩展结构预留键位。

## 第一版落地范围

第一版只做：

```text
1. EventRouletteController.gd
2. 四模式触发频率
3. 颜色轮盘 + 效果轮盘流程
4. 六个基础效果
5. 控制仓干扰 5 秒
6. 中央横幅提示
7. 右下角 HUD 显示当前事件和下次事件倒计时
8. 存档记录事件倒计时
```

暂时不做：

```text
特殊球
特殊口
复杂连锁事件
传送门
全局天气
多事件叠加
```

## 建议开发顺序

为了第一版最稳，建议按下面顺序落地：

1. 先给 `ControlChamber.gd` 和 `Turret.gd` 补齐最小事件接口。
2. 新建 `EventRouletteController.gd`，只跑计时、抽阵营、抽效果、执行结果，不先做复杂动画。
3. 接中央横幅和右下角 HUD 文本。
4. 接存档字段，只保存倒计时和最近事件。
5. 确认基础模式、占领模式、限时模式、狂野模式都能独立进入事件循环。

这样可以先把玩法骨架跑通，再逐步补“综艺感”表现层。

## 最终简化规则图

```text
事件计时到
    ↓
启动事件转盘
    ↓
颜色轮盘转动
    ↓
根据事件性质和局势权重选中阵营
    ↓
效果轮盘转动
    ↓
六选一：重转 / +10 / x2 / x3 / 加1球 / 控制仓干扰
    ↓
未锁定：立即作用于 pending_count 或控制仓
锁定中：正向效果进入下一轮
干扰类：立即打断并封锁
    ↓
中央横幅显示结果
    ↓
开始下一次事件倒计时
```

这版规划的核心优点是：随机性增强，但所有随机仍围绕控制仓运行，不会破坏“控制仓决定炮台发射”的核心玩法。
